## The Reality of This Meeting

- You're on camera from Vancouver
- They're sitting in conference rooms, maybe uncomfortable
- Some relationships are tense, some are fine
- People are worried about roles, jobs, direction
- This is NOT a stage presentation
- This is a team meeting where you're sharing work

**The goal:** Share what you've built, invite collaboration, don't threaten anyone's position.

## Full Spoken Delivery

---

**[Camera on. Normal energy. Don't over-perform.]**

Hey everyone. Thanks for joining.

[brief pause]

So Roy asked me to share what I've been working on with vintage. I'll walk through it and then I'd really like to hear what you all think - where this fits, what's missing, what could be better.

[pause]

### What This Is

I've been building a vintage engine.

It produces the curves, lift calculations, confidence intervals - the output we give to stakeholders.

[pause]

The reason I'm sharing it now is that it's reached a point where it's working - six campaigns are running through it - and I want to get input before I go further.

[pause]

---

### How It's Structured

**[Keep this conversational, not lecturing]**

Quick overview of the structure.

There are four modules.

Experiment Metadata - who's in the test. This pulls from existing sources.

Campaign Metadata - what we're measuring. Right now I'm configuring this per campaign.

Success Definitions - how we calculate success. Also configured per campaign.

Client Journey - the outcomes. Email feedback, channel data. Pulls from existing sources.

[pause]

The engine takes input from these modules and calculates the curves.

[pause]

I built it to connect with Roy's Super Fact framework - so the experiment metadata aligns with that structure. And the success definitions are set up so they could eventually plug into Daniel's Success Library work.

[pause]

---

### Where It Is Today

Six campaigns running: VCN, VDA, VDT, VUI, VUT, VAW.

[pause]

Two ways to see the output right now.

One is the enterprise dashboard path - we're working with Frank and Kelvin's teams on that. Still figuring out the details.

The other is an in-house dashboard I built - it's deployed, you can see it now. I mainly built it to help me understand the data while we figure out the enterprise path.

[pause]

**[Check in here]**

I can pause here if there are questions about what I've described so far. Or I can keep going and we do questions at the end - whatever works.

[wait for response]

---

### What I'm Thinking About Next

**[After questions or if they say keep going]**

A few things I'm thinking about for next steps.

[pause]

**Connecting to the libraries.** Right now I'm hardcoding success definitions. The plan is to eventually pull those from the Success Library once that's ready. Same with campaign metadata - could come from a catalog instead of being configured manually.

**Automation.** Right now I run this manually. There might be opportunity to schedule it, automate the refresh. I don't know what that looks like yet.

**The enterprise dashboard.** Need to figure out refresh cadence, data format, how it gets maintained.

[pause]

---

### Where I Could Use Input

**[This is the invitation - genuine, not performative]**

Honestly, I could use input on a few things.

[pause]

What secondary metrics would be useful? Right now it's primary success metrics. But if there are engagement metrics or segment breakdowns that would help, I can add those.

How often do stakeholders actually need refreshed curves? Weekly? Monthly? That affects how we set this up.

And - does anyone want to be involved in this? Whether that's the codebase, the definitions, the dashboard design - I'm not trying to own this alone. Akash is setting up the GitHub repo and the idea is this becomes something the team can contribute to.

[pause]

---

### That's It

**[Simple close. Don't over-deliver.]**

That's basically where I am.

Six campaigns working. Two output paths. Built to connect with the frameworks we're developing.

[pause]

What questions do you have? What am I missing?

[pause]

**[Let silence happen. Don't fill it. Let them process.]**

## Delivery Notes for Remote Meeting

| Aspect | Guidance |
|--------|----------|
| **Camera** | Look at the webcam, not the screen. That's eye contact. |
| **Energy** | Meeting energy. Not keynote. Not flat either - engaged but calm. |
| **Pace** | Slower than you think. Remote has delay. Let things land. |
| **Check-ins** | Pause and ask "questions so far?" at natural breaks. |
| **Silence** | Let it happen. People in rooms need time to unmute or speak up. |
| **Don't over-perform** | This isn't a TED talk. It's a team meeting. Be normal. |
| **Body language** | Visible hand gestures help. Don't be stiff. |
| **Invite early** | "I'd really like to hear what you think" - in the first minute. |

---

## Handling the Anxious Room

| Signal | Response |
|--------|----------|
| Silence after you finish | Let it sit. Count to 5 in your head. Someone will speak. |
| Skeptical questions | Take them seriously. "That's a good question. Here's what I'm thinking..." |
| Someone seems defensive | Don't push. Acknowledge their work. "This connects to what [name] has been doing..." |
| No engagement | Ask a specific person a specific question. "Daniel, does this make sense with the Success Library direction?" |
| Someone talks over you | Let them. Don't compete. Finish when they're done. |

## Key Phrases That Create Safety

| Phrase | Why It Works |
|--------|--------------|
| "I'd really like to hear what you think" | Invites, doesn't demand |
| "Before I go further" | Shows you're not steamrolling |
| "I don't know what that looks like yet" | Honest about uncertainty |
| "I'm not trying to own this alone" | Explicitly opens the door |
| "What am I missing?" | Positions them as experts |
| "Does anyone want to be involved?" | Direct invitation |
